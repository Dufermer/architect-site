## Draft Post: W1 Day 3 — X/Twitter Thread (EN) — "Why Astro.js?"

**Post 1/4:**
> We evaluated 5 SSGs for Architect. Here's why we chose Astro.js over Next.js, VitePress, Hugo, and Eleventy.

**Post 2/4:**
> The constraint: our landing page needs to be static + fast (Cloudflare), our blog needs MDX, our docs need a sidebar.
>
> Astro handles all three natively:
> - Static by default → instant on Cloudflare
> - Built-in MDX support → no plugin hell
> - Content collections → structured docs

**Post 3/4:**
> Why not Next.js?
> - Overkill for a mostly static site
> - Server costs for something that could be static
> - Heavier bundle, slower builds
>
> Astro's Islands architecture means we ship 0 JS unless needed. Landing page: <10KB.

**Post 4/4:**
> Dev experience comparison (our data):
> - Astro: 5min to first page
> - Next.js: 30min with create-next-app
> - Hugo: 15min but Go templates are painful
> - Eleventy: 10min but zero ecosystem
>
> Astro won on speed + DX + ecosystem. No regrets.
